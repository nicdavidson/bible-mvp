# Bug Review (2026-10-05)

Scope: backend correctness, deploy/infra, service worker and offline. The UI navigation bugs are covered separately in `UI_OVERHAUL.md`. Repros ran against a scratch copy of the DB and read-only against bible-mvp-dev (never prod).
Status means what was done on branch `fix/bug-review`.

| # | Sev | Finding | Status |
|---|---|---|---|
| 1 | High | **The service worker never controlled the app.** It was registered from `/static/sw.js` with no scope and no `Service-Worker-Allowed` header, so its scope was `/static/`. The offline shell never worked, and data downloaded to IndexedDB was unusable offline because the page itself wouldn't load. Confirmed on dev: `scope=/static/`, `controller=null`. | **Fixed.** Registered with `{scope:'/'}`, and the server sends `Service-Worker-Allowed: /`. Verified in a browser: with the network off, reloading `/John/3` renders the chapter. |
| 2 | High | **"Download for offline" silently dropped most of the data.** It requested chapters every ~50 ms against a 120/min limit, never retried a 429, and still said "Download complete!". | **Fixed.** Requests retry with backoff on 429 or 5xx (honouring `Retry-After`). Failures are counted, and the toast reports them instead of saying "complete". The real fix is per-book offline bundles, which are on the roadmap. |
| 3 | High | **`entrypoint.sh` didn't check `cp`, so a failed copy became permanent.** The manifest was written even if the DB copy failed, and a truncated DB was then treated as "up to date". `/api/health` still returned 200. | **Fixed.** The copy goes to a temp file, its sha256 is checked against the manifest, and only then is it renamed into place, with the manifest written last. Any stale journal is removed first. `set -eu` makes a failed copy fail the boot. `/api/health` returns 503 when `verses` is empty. Both the happy path and the sha-mismatch path were tested in a sandbox. |
| 4 | High | **Verse-range DoS on `/api/crossref-map/{ref}`.** `John 1:1-30000000` pinned a core for over 4 minutes. | **Fixed.** The range is clamped to 200 verses. |
| 5 | Med | **Integers over 2^63 returned a 500** (`OverflowError` at SQLite binding). | **Fixed.** A global handler returns 400. |
| 6 | Med | **Service-worker bugs that would bite once #1 was fixed.** A cache failure turned a good response into an offline error. The content cache was wiped on every deploy. The precache missed every `?v=` URL. `addAll` could pick up stale HTTP-cache copies. `/config.js` wasn't precached. | **Fixed by rewriting `sw.js`** (about 100 lines, previously about 240). It precaches the exact URLs `index.html` requests with `cache:'reload'`. The content cache survives deploys. Cache writes are fire-and-forget. Navigations fall back to the cached shell. The unused postMessage-to-IndexedDB path is removed, since the app writes IndexedDB itself. HTML is served with `Cache-Control: no-cache`. |
| 7 | Med | **"Refresh offline data" deleted the offline data** (`clearAll()`). | **Fixed.** It refreshes the lexicon. Chapters already refresh in the background as they're read. |
| 8 | Med | **Boot time vs the health-check grace period.** If a rebuilt DB skips `add_commentary_links.py`, the startup migration takes about 40 s. | **Mitigated.** `grace_period` raised to 120 s. **Open:** move those migrations into the DB build so runtime is read-only. |
| 9 | Low–Med | Promote workflow issues: input injection, short SHAs, an unpinned action. | **Fixed** as part of the security review (env plus 40-char validation, pinned action). The `jq '.[0]'` path was verified against real `flyctl image show --json` output. **Open:** "blank = whatever dev runs" can promote an image whose dev smoke test failed, so check the dev run before promoting. |
| 10 | Low | Parser gaps: `Rom. 3:23`, `Exo 20`, `1john 3`, and reversed ranges such as `3:18-16`. | **Fixed.** |
| 10 | Low | IndexedDB interlinear keys ignore the translation. A duplicate Ezekiel 40:1 commentary key. HEAD returns 405. `/John/abc` returns a 422 JSON error. Spurgeon is stored in localStorage (about 1.7 MB). The `find-path` seed mismatch. Topic previews always use BSB. | **Open.** These are low impact. |

**Not done here, and worth doing:**
- The volume is 1 GB. The atomic copy needs room for the old DB plus the new one (about 770 MB today). **Grow the volume to 3 GB before the DB passes about 450 MB.**
- Test gaps: `TestClient` without `with` never runs the lifespan or migrations. Nothing covers the entrypoint, the SW or the offline JS, except the Playwright repro scripts used in this review, which aren't in the repo yet.
